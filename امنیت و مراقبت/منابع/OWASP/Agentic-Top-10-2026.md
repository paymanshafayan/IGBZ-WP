## بخش‌های استفاده‌شده

### ASI02 — سوءاستفاده از ابزار

عامل ممکن است با ابزار معتبر ولی پرقدرت، خروجی مدل یا محتوای تزریق‌شده را به حذف، انتشار،
انتقال پول، استخراج داده یا حلقهٔ پرهزینه تبدیل کند. راهکارهای مرتبط برای IGBZ:

- ابزار با scope، سقف نرخ و egress allowlist؛
- احراز و مجوز در سطح هر عمل؛
- preview یا dry-run پیش از عمل حساس؛
- middleware سیاست‌گذار که خروجی مدل را غیرقابل‌اعتماد بداند؛
- credential کوتاه‌عمر و budget؛
- لاگ تغییرناپذیر و تشخیص الگوی غیرعادی ابزارها.

### ASI03 — سوءاستفاده از هویت و اختیار

خطر اصلی در معماری چندعامل، انتقال اختیار مدیر یا عامل قوی به عامل ضعیف، اعتماد داخلی
پیش‌فرض، credential مشترک و ادامهٔ workflow پس از منقضی‌شدن مجوز است. کنترل‌های مرتبط:

- هویت مستقل integration برای هر زیرسایت؛
- token مقید به task، subject، resource، purpose و duration؛
- بازبینی مجوز در لحظهٔ هر اقدام، نه فقط آغاز workflow؛
- جداسازی session/context و ممنوعیت ارث‌بری اختیار؛
- تأیید انسانی برای افزایش اختیار یا عمل برگشت‌ناپذیر.

### ASI07 — ارتباط ناامن میان عامل‌ها

پیام API یا صف بین پادو، افزونه و orchestrator نباید صرفاً به‌خاطر «داخلی» بودن معتبر
فرض شود. سند امضای پیام، hash کردن payload و context، nonce/timestamp، anti-replay،
احراز متقابل و سیاست نسخه/capability در gateway را توصیه می‌کند.

### ASI04/ASI05/ASI06 — زنجیرهٔ تأمین، اجرای کد و حافظه

اسکیل، tool descriptor، MCP، prompt، artefact و memory همگی سطح حمله‌اند. برای IGBZ:

- اسکیل و قرارداد باید منبع، نسخه، hash/امضا و kill switch داشته باشند؛
- کد تولیدی عامل مستقیم روی تولید اجرا نشود؛
- تولید از اجرا با validation و approval جدا بماند؛
- حافظه و context میان فروشگاه‌ها جدا و ورودی حافظه دارای provenance/بازبینی باشد.

## اثر مستقیم بر تصمیم پروژه

پادوی هر فروشگاه سرویس بیرونی و از دید پلتفرم **غیرقابل‌اعتماد** است. اتصال آن فقط API
ابزار محدود همان زیرسایت را می‌بیند؛ به DB، فایل، shell، wp-admin، n8n، ویرا یا REST عمومی
ووکامرس دسترسی ندارد. هر خروجی پیش از اجرا schema validation، مجوز بک‌اند، audit و برای
عمل حساس تأیید انسانی می‌گیرد.

این فایل فقط پشتوانهٔ تصمیم است و اثبات پیاده‌سازی نیست. credential کوتاه‌عمر، امضای پیام،
ضد replay، ابزارهای محدود و آزمون خصمانه هنوز کد ندارند و در کارهای باقی‌مانده می‌مانند.
