# تست ویژوال صفحهٔ مرکزی ارائه‌دهنده‌های هوش مصنوعی (تصحیح ADR-0005) — قاعدهٔ ۱۲

تاریخ: ۱۴۰۵/۰۶/۱۱ (2026-09-01) · Chromium 149 (پلی‌رایت‌کور + @sparticuz/chromium) · WordPress 7.0.4 (Playground PHP-Wasm)

## هدف

تصحیح قلمرو مجوز: مدیریت ارائه‌دهنده (رکوردها، مسیریابی بخش‌ها، کلیدهای پنل) به کنترل پنل
مرکزی IGBZ منتقل و فقط برای مدیر ارشد (`MANAGE_SUITE`) باز شد. ادمین فروشگاه دیگر هیچ
راهی برای تغییر ارائه‌دهنده ندارد.

## صفحهٔ هدف

- `wp-admin/admin.php?page=igbz-ai-providers` — صفحهٔ جدید مرکزی «ارائه‌دهنده‌های هوش مصنوعی».
- `wp-admin/admin.php?page=igbz-pado&tab=settings` — پنل فروشگاه (باید از provider پاک باشد).

| بررسی | وضعیت |
|---|---|
| صفحهٔ مرکزی رندر می‌شود؛ `h1` = «ارائه‌دهنده‌های هوش مصنوعی» | ✅ |
| RTL (`dir="rtl"`) | ✅ |
| زبان (`lang="fa-IR"`) | ✅ |

| صفحهٔ «ثبت کلیدها» (سطح یک): دقیقاً دو ورودی کلید + یک دکمهٔ «ثبت کلیدها» + یک ⚙ | ✅ |
| بازشدن پنل با ⚙ (`#igbz-provider-panel` display=block) | ✅ |
| پنل (سطح دو): کلید «استفاده از یک ارائه‌دهنده برای هر دو بخش» + انتخاب ارائه‌دهنده/مدل برای دو بخش | ✅ |
| فرم افزودن/ویرایش ارائه‌دهنده + جدول ارائه‌دهنده‌های ثبت‌شده | ✅ |

## مجوز

گیت `MANAGE_SUITE` در سه لایه اعمال شده است: ثبت منو (`Menu::add`)، رندر صفحه
(`Capabilities::require`) و همهٔ handler های `admin_post`. نقش `igbz_tenant_owner`
(ادمین فروشگاه) قابلیت `MANAGE_SUITE` ندارد (در `Activator::add_roles` تعریف شده و
ماتریس قابلیت‌ها با `DriftGuardTest` به ۱۱ عضو پین شده است)، بنابراین هیچ مسیری برای
تغییر provider در دسترس ادمین فروشگاه نیست.
