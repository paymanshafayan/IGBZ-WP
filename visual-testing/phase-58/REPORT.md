# گزارش تست ویژوال — فاز ۵۸ (اتصال عملیات حساس به صف مجوز)

تاریخ: ۱۴۰۶/۰۶/۰۹ (۲۹ اوت ۲۰۲۶) · ابزار: Chromium واقعی (Playwright 1.62.1 + @sparticuz/chromium 149)

## سطح بازبینی‌شده

تب «درخواست‌های مجوز» مرکز پادو (`wp-admin/admin.php?page=igbz-pado&tab=approvals`)
با سه ردیف واقعیِ عملیات حساس فاز ۵۸ در انتظار (دو تغییر قیمت + حذف انبوه ۲ محصول)
و نمای وضعیت «اجرا شده» با ۵ ردیف اجراشده از دود زنده.

## نتیجه

| بررسی | نتیجه |
|---|---|
| رندر تب مجوزها + ردیف‌های سه نوع حساس (قیمت/بازپرداخت/حذف انبوه) | ✅ (۴ ردیف pending) |
| محتوای payload فنی هر ردیف (JSON قدیمی/جدید قیمت) | ✅ |
| نمای executed (فیلتر وضعیت) | ✅ ۵ ردیف |
| سرریز افقی | ۰ پیکسل ✅ |
| خطای JS | ۰ ✅ |
| تصویر خراب | ۵ — همهٔ بیرونی: ۱ gravatar + ۴ ایموجی twemoji از CDN جی‌اس‌دلivr؛ سندباکس به شبکهٔ بیرونی دست ندارد (مورد شناخته‌شده از فازهای پیشین، خارج از کد افزونه) |

## محدودیت صادقانه

بینایی مدل در این جلسه خاموش بود؛ بازبینی «چشمی» مستقیم ممکن نشد. شواهد این گزارش:
DOM خوانده‌شده توسط کرومیوم واقعی (عنوان، ردیف‌ها، سرریز، خطای کنسول، تصاویر) +
دو اسکرین‌شات تمام‌صفحهٔ ضمیمه برای بازبینی کارفرما:
`pado-approvals-pending.png` و `pado-approvals-history.png`.

## تأیید زندهٔ همراه

دود ۱۹گامی `/?igbz_ops_smoke=1` همه‌سبز: تغییر قیمت واقعی (regular + فعال) روی محصول
واقعی ووکامرنس، بازیابی از مسیر خود صف، محصول دارای حراج (regular عوض شد، حراج
سرو می‌ماند)، بازپرداخت پرداختِ ادانشده رد و ردیف failed، دفتر refunds دست‌نخورده،
حذف انبوه فقط زباله‌دان + بازیابی. جزئیات در PROJECT-STATE §۱۱.۱۴.
