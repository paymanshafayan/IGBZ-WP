# ویرا

یک دستیار عامل (agent) که **روی دستگاه خودت** اجرا می‌شود، **ابزار واقعی** دارد
(خواندن و نوشتن فایل، اجرای فرمان، جستجو، وب)، **اسکیل و پلاگین** نصب می‌کند، به
**MCP server** وصل می‌شود، و با **هر پرووایدری** کار می‌کند.

نسخهٔ **۰.۹.۶** — هسته، رابط بازساخته روی طرح تأییدشده، **دوزبانه (فارسی/انگلیسی)**،
آیکون‌های Font Awesome Pro، **مخزن و شاخهٔ قفل‌شونده در هر گفتگو**، هاب پرووایدر با
مسیریابی خودکار و عیب‌یاب، حالت بدون‌رابط، SDK، و سندباکس کانتینری که **پیش‌فرض روشن** است.

## نصب

نیاز: **Node.js نسخهٔ ۲۰ یا بالاتر** ([nodejs.org](https://nodejs.org)).

**ساده‌ترین راه — از ریشهٔ مخزن، بدون هیچ `cd`:**

```powershell
.\vira.cmd                       # ویندوز
```

```bash
./vira.sh                        # لینوکس و مک
```

این دو اسکریپت خودشان به پوشهٔ درست می‌روند، اگر `node_modules` نباشد یک بار `npm ci`
می‌زنند، و بعد ویرا را بالا می‌آورند. هر گزینه‌ای که بدهی مستقیم رد می‌شود:
`.\vira.cmd --port 7788 --no-open`

**راه دستی:**

```bash
cd vira
npm ci            # نه npm install — دلیلش پایین‌تر
node src/cli.js
```

### خطای `MODULE_NOT_FOUND` یعنی پوشهٔ اشتباه

اگر `node src/cli.js` را از **ریشهٔ مخزن** بزنی (به‌جای داخل `vira`), این را می‌گیری:

```
Error: Cannot find module '...\IGBZ-WP\src\cli.js'
code: 'MODULE_NOT_FOUND', requireStack: []
```

`requireStack: []` یعنی خودِ فایل ورودی پیدا نشده، نه یک وابستگی. سه راه حل:

```powershell
.\vira.cmd                       # از ریشه، توصیه‌شده
node vira\src\cli.js             # از ریشه، دستی
cd vira; node src\cli.js          # از داخل پوشه
```

**چرا `npm ci` و نه `npm install`:** `npm install` قفل وابستگی‌ها
(`package-lock.json`) را بازنویسی می‌کند. آن فایل در گیت هست، پس بعدش `git pull` بعدی با
پیام «local changes would be overwritten» رد می‌شود — برای فایلی که هیچ‌وقت دستش نزده‌ای.
`npm ci` دقیقاً همان چیزی را نصب می‌کند که در قفل نوشته شده و قفل را دست نمی‌زند.

همین. پنجره (یا مرورگر) روی `http://127.0.0.1:7788` باز می‌شود.

### اگر دستور سراسری `vira` می‌خواهی، **`npm link` بزن نه `npm install -g .`**

```bash
cd vira
npm link          # درست: پیوند به همین پوشه
```

```bash
npm install -g .  # غلط: یک کپیِ منجمد می‌سازد
```

`npm install -g .` پوشه را **کپی** می‌کند. از آن لحظه به بعد، دستور `vira` همان کپی را
اجرا می‌کند و هر `git pull` ای که بزنی، هیچ اثری روی آن ندارد — ابزار تا ابد همان نسخهٔ روز
نصب می‌ماند. `npm link` به‌جای کپی، **پیوند** می‌سازد و همیشه کد مخزن را اجرا می‌کند.

برای اینکه این اشتباه ساکت نماند، ویرا **خودش تشخیص می‌دهد** که از کجا اجرا شده و اگر
کپیِ منجمد باشد، هم روی ترمینال داد می‌زند و هم یک نوار در بالای خود برنامه می‌گذارد:

```
  ویرا 0.8.0 · ساخت 5c9f6b3 · 2026-08-17 23:32
  آدرس:       http://127.0.0.1:7788
  پوشهٔ کاری:  /path/to/project
  اجرا از:     /path/to/IGBZ-WP/vira
```

### «مطمئنم pull کردم، ولی نسخه عوض نشده»

عدد نسخه فقط وقتی جلو می‌رود که کسی دستی بالایش ببرد. برای همین کنارش **شناسهٔ کامیت**
هم چاپ می‌شود، که با هر تغییر خودکار عوض می‌شود. اگر بعد از `git pull` همان شناسهٔ قبلی
را دیدی، یعنی pull واقعاً چیزی نیاورده یا کدِ دیگری اجرا می‌شود:

```powershell
.\vira.cmd --version      # نسخه، شناسهٔ ساخت، و مسیر واقعی کد
git log -1 --format=%h      # شناسهٔ کامیتی که روی دیسک داری
```

اگر این دو یکی نبودند، چیزی بین pull و اجرا فاصله انداخته. همین را در برنامه هم می‌بینی:
با نگه‌داشتن ماوس روی شمارهٔ نسخه در نوار کناری، و کامل‌تر در **تنظیمات ← وضعیت و تشخیص**.

اگر به‌جای مسیر مخزن، مسیری داخل `node_modules` ببینی، این را هم می‌بینی:

```
  ⚠  این یک کپیِ نصب‌شده است، نه کد مخزن.
     هر تغییری که در مخزن بدهی، اینجا دیده نمی‌شود.
     درستش:  npm rm -g vira   سپس در پوشهٔ مخزن:  npm link
```

### وقتی نسخهٔ قدیمی بالا می‌آید

نشانه: `git pull` زده‌ای ولی برنامه هنوز نسخهٔ قبلی را نشان می‌دهد. روی ویندوز
(PowerShell):

```powershell
npm ls -g --depth=0                  # ببین vira نصب سراسری هست یا نه
npm rm -g vira                     # کپیِ منجمد را بردار
cd C:\مسیر\IGBZ-WP\vira
git pull
npm install
npm link                             # از این به بعد، دستور vira همین کد را اجرا می‌کند
vira --version                     # باید نسخهٔ مخزن را بدهد
```

نسخه از `package.json` خوانده می‌شود، نه از رشته‌ای در کد — یک تست هم هست که اگر کسی
دوباره نسخه را جایی دستی بنویسد، قرمز می‌شود. صفحهٔ **تنظیمات ← وضعیت و تشخیص** هم مسیر
واقعی کدی که اجرا می‌شود را نشان می‌دهد.

### گزینه‌ها

```
vira --dir /path/to/project   پوشهٔ کاری
vira --port 7788              پورت
vira --host 0.0.0.0           شنیدن روی شبکه (پیش‌فرض فقط لوکال)
vira --no-open                پنجره باز نشود
```

### حالت بدون‌رابط (headless)

برای اسکریپت، CI، و هر جایی که پنجره معنا ندارد:

```bash
vira -p "تست‌ها را اجرا کن و اگر قرمز شد دلیلش را بگو"
vira -p - < task.txt                       # پرامپت از ورودی استاندارد
vira -p "بازبینی کن" --output-format json  # خروجی ماشین‌خوان
vira -p "…" --output-format stream-json    # هر رویداد، یک خط JSON
vira -p "…" --mode auto                    # بدون تأیید
vira -p "…" --allow "bash:npm test"        # فقط همین یکی بی‌پرسش
vira -p "…" --allowed-tools read_file,grep # دست مدل را ببند
vira -p "…" --max-turns 8 --model gpt-4o
```

> در این حالت **هر ابزاری که تأیید بخواهد رد می‌شود**، مگر `--mode auto` بدهی یا با
> `--allow` قاعده بگذاری. یک اسکریپت خودکار نباید بی‌سروصدا اجازهٔ کار خطرناک بگیرد.
> کد خروج: `0` موفق · `1` خطا در اجرا · `2` پرامپت خالی · `3` تنظیمات ناقص.

### استفاده به‌عنوان کتابخانه

```js
import { query, createVira } from 'vira';

const out = await query( { prompt: 'این پروژه چه می‌کند؟', workspace: '.', mode: 'plan' } );
console.log( out.text, out.usage );

const h = await createVira( { workspace: '.', onEvent: ( e ) => console.log( e.type ) } );
h.onPermission( ( req ) => req.name === 'read_file' );      // تصمیم با تو
h.onQuestion( () => 'راه تمیز' );
await h.send( 'یک تست برای src/diff.js بنویس' );
await h.close();
```

### پنجرهٔ مستقل (اختیاری، بدون نصب چیزی)

در Chrome یا Edge روی آیکون **Install** در نوار آدرس بزن — ویرا در یک پنجرهٔ جدا بدون نوار
مرورگر باز می‌شود. برای کار روزمره همین کافی است.

پوستهٔ Electron هم در `desktop/main.js` هست (`npm i -D electron && npm run desktop`)، ولی
مسیر پیش‌فرض همان وب‌اپ است.

## هاب پرووایدر

تا نسخهٔ ۰.۶ ویرا **یک** پرووایدر فعال داشت. از ۰.۷ می‌توانی یک **هاب** بسازی: هر تعداد
اتصال، هر تعداد مدل، و ویرا خودش تصمیم می‌گیرد هر درخواست کجا برود.

فرق مهمش با یک مسیریاب معمولی: پیشوند دستی (`auto/coding`) نمی‌خواهد. **جنس درخواست را
خودش تشخیص می‌دهد** و بعد از چند نوبت، از نتیجهٔ واقعی همین نصب یاد می‌گیرد کدام مدل
برای کدام کار بهتر است.

```
اتصال (چند حساب، چند سرویس)  →  مدل (با قیمت، توانایی، برچسب)  →  ترکیب (زنجیره + راهبرد)
                                          ↓
                             دستهٔ کار → کدام ترکیب
```

### صفحهٔ تمام‌قد «هاب پرووایدر» (از ۰.۹.۴)

شش تبِ تنظیمات یکی شد و به یک صفحهٔ تمام‌قد در ستون «امکانات» نشست، با چهار نما:

| نما | چه کاری آنجا می‌کنی |
|---|---|
| **نگاه کلی** | نقشهٔ توپولوژی هاب: رنگ هر گره وضعیت واقعی اتصال است، ضخامت یال ترافیک ثبت‌شده، و روی گرهٔ خطادار دکمهٔ «ریست و رفع خطا» |
| **اتصال‌ها** | کاتالوگ کارتیِ همیشه‌نمایان (Test روی کارت) → جزئیات هر سرویس: اتصال‌هایش (چند حساب) + مدل‌هایش با کشف، آزمون تک‌مدل، آزمون همه، فیلتر رایگان/پولانی و مخفی‌کردن شکست‌خورده‌ها. افزودن = ویزارد چهارگامی (سرویس → شناسنامه → تست زنده → نتیجه) |
| **ترکیب‌ها** | ویزارد چهارگامی ترکیب (نام → مدل‌ها با جابه‌جایی → راهبرد در دو گروه هوشمند/قطعی → بازبینی) + راهبرد پیش‌فرض + دستهٔ کار + آزمون «این درخواست به کجا می‌رود» |
| **سلامت و مصرف** | کارت‌های آماری، مدارشکن‌ها با «بازکردن دوباره»، **ریست کل سلامت**، سه سقف هزینه، عیب‌یاب، دفتر راه‌حل‌ها، کش و اندپوینت |

### پراکسی و موتور تونل (۰.۹.۵ + ۰.۹.۶)

Node.js برخلاف مرورگر، پراکسی سیستم (Hiddify، v2rayN، Clash…) را خودکار استفاده
نمی‌کند؛ تماس‌های پرووایدر مستقیم می‌روند و از IP ایران پاسخ ۴۲۹/۴۰۳ می‌آید.

**تنظیمات ← پراکسی** (صفحهٔ سبکِ صفحهٔ پراکسی ویندوز): حالت خاموش/دستی/موتور ·
نشانی+درگاه (مثال Hiddify: `127.0.0.1` / `7890`) · **استثناها** با «؛» و `*` · تیک
«برای نشانی‌های محلی از پراکسی استفاده نشود» · Save · «تست اتصال» (مقایسهٔ IP و
تأخیر با/بدون پراکسی) · فیلد پراکسی مخصوص هر اتصال در ویزارد هاب.

**موتور تونل داخلی** (۰.۹.۶): مثل یک v2ray داخل ویرا — هستهٔ رسمی **xray** را
دانلود می‌کند، کانفیگ رایگان را از شش مخزنِ پیش‌فرضِ راستی‌آزمایی‌شده
(ebrasha، barry-far، V2ray-Collector، FreeFolksOn، Freedom-V2Ray،
Delta-Kronecker؛ قابل ویرایش) جمع می‌آورد، `vmess/vless/trojan/ss` و اشتراک base64
را می‌پارسد، هر کانفیگ را جداگانه می‌آزماید (تأخیر + IP)، سالم‌ها را با سنجاق نگه
می‌دارد و یک **درگاه محلی پایدار** (socks:7809 + http:7810) می‌سازد که هر دقیقه
سلامتش بررسی و در صورت شکست، خودکار روی کانفیگ بعدیِ سالم می‌چرخد. حالت «موتور»
یعنی همهٔ تماس‌های پرووایدر خودکار از همین درگاه می‌گذرند؛ مقصدهای محلی همیشه
مستقیم‌اند. هشدار: کانفیگ رایگان یعنی اپراتور ناشناس — برای کار حساس، سرور خودت
را به منابع اضافه کن.

**تنظیمات ← لاگ‌ها** (۰.۹.۶): سطح/کانال/جستجو · زمینهٔ JSON هر ردیف · خروجی JSON ·
پاک‌کردن. نسخهٔ کامل روی دیسک: `~/.vira/logs/vira.log`.

**راه‌انداز** (۰.۹.۹): `vira.cmd` / `vira.sh` دیگر **خودشان `npm ci` نمی‌زنند**.
در ۰.۹.۶ این کار خودکار بود، ولی نشانه‌اش را به **نسخهٔ** `package.json` گره زده
بودیم و نسخه با هر تغییر کد بالا می‌رود — یعنی عملاً بعد از هر `git pull` یک نصب
کامل اجرا می‌شد، حتی وقتی هیچ وابستگی‌ای عوض نشده بود. حالا اگر `node_modules`
نباشد فقط یک خط راهنما چاپ می‌شود:

```
وابستگی‌ها نصب نیستند. یک بار این را بزن:

    cd <مسیر>/vira && npm ci
```

`npm ci` را فقط وقتی بزن که خودت وابستگی‌ها را عوض کرده‌ای یا این پیام را دیدی.

ریست در سه سطح: مدل (`reset-breaker`)، اتصال (`reset-provider` — مدارشکن‌ها و خطاها و
پرچم پایان اعتبار همهٔ مدل‌های آن اتصال) و کل هاب (`reset-health`). نوار بالای صفحه
سه حالت دارد و همیشه **گام بعدیِ درست** را می‌گوید؛ «پروفایل تک‌نفره» هم دیگر رقیب
هم‌عرض نیست — پانوشت نمای اتصال‌هاست. (طرح کامل: `DESIGN-PROVIDER-UI.md`.)

### راهبردها

`auto` (امتیازدهی زنده) · `priority` · `weighted` · `round-robin` · `least-used` ·
`fill-first` · `cost-optimized` · `fastest` · `p2c`

حالت `auto` روی نُه عامل امتیاز می‌دهد: یادگیری از نتیجه، تناسب برچسب، نرخ موفقیت،
تأخیر، هزینه، سهمیهٔ باقی‌مانده، وضعیت مدارشکن، خطاهای اخیر، و ظرفیت هم‌زمانی.
**وزن یادگیری از همه بیشتر است** — چون جدول ترجیحی که امروز بنویسیم، سه ماه دیگر کهنه است.

### عیب‌یاب هاب

وقتی یک درخواست شکست می‌خورد، ویرا به‌جای اینکه فقط خطا نشان بدهد، یک نردبان چهارپله
را بالا می‌رود:

| پله | کار | هزینه |
|---|---|---|
| ۱ | **دفتر راه‌حل‌ها** — این امضای خطا قبلاً دیده شده؟ همان وصله را بزن | صفر |
| ۲ | **تعمیر قاعده‌ای** — `/v1` جامانده، پارامتر پشتیبانی‌نشده، نقش system رد شد، `max_tokens` اجباری، استریم نیست، ۴۲۹ | صفر |
| ۳ | **مدل عیب‌یاب** — متن خطای **پاک‌سازی‌شده** را می‌خواند و وصلهٔ ساختاریافته پیشنهاد می‌دهد | یک تماس |
| ۴ | **تأیید** — درخواست دوباره اجرا می‌شود؛ فقط اگر واقعاً جواب داد ثبت می‌شود | — |

چهار قید که بدون آن‌ها این ایده خطرناک است، و هر چهار در کد و تست هستند:

1. **وصله شیء ساختاریافته است، نه کد.** فهرست بسته: `set_base_url` · `drop_param` ·
   `set_param` · `add_header` · `set_auth_style` · `disable_stream` · `reshape_messages` ·
   `backoff_retry`. سخت‌گیرانه‌ترین قاعده: `set_base_url` اجازه ندارد **میزبان** را عوض
   کند — وگرنه یک مدل می‌توانست با یک «وصله» همهٔ ترافیک را به سرور خودش ببرد.
2. **عیب‌یاب مدارشکن و بودجهٔ جدای خودش را دارد.** صد خطای هم‌امضا صد تماس نمی‌سازد.
3. **راه‌حل بدون آزمون ثبت نمی‌شود.** «فکر می‌کنم مشکل این است» ارزش ذخیره ندارد.
4. **دفتر دیدنی و برگشت‌پذیر است.** چه یاد گرفته، از کِی، چند بار جواب داده، و دکمهٔ حذف.

**پایان اعتبار خطا نیست، یک واقعیت است.** آنجا عیب‌یاب دخالت نمی‌کند: اتصال «خالی»
علامت می‌خورد و درخواست به گزینهٔ بعدی می‌رود.

**موقت در برابر دائمی:** وصلهٔ آزموده‌شده **موقت** ثبت می‌شود و فقط بعد از خطا اعمال
می‌شود. وقتی مدیر دکمهٔ «ماندگار کن» را بزند، وصله روی خود اتصال می‌نشیند و از آن به بعد
**پیش از اولین تلاش** اعمال می‌شود — یعنی دیگر حتی یک درخواست هم هدر نمی‌رود.

### خروجی سازگار با OpenAI

هاب خودش یک سرویس سازگار با OpenAI هم هست، تا بقیهٔ اجزای فروشگاه (مترجم، خلاصه‌ساز، …)
از همان یک جا کلید، هزینه و سلامت بگیرند:

```
GET  /v1/models
POST /v1/chat/completions      (با stream و بدون stream)
```

مدل می‌تواند `auto` باشد (مسیریابی کامل)، `combo:<شناسه>` (یک ترکیب مشخص)، یا
`<اتصال>::<مدل>` (سنجاق‌کردن به یک مدل).

فقط روی لوکال‌هاست: طبق تصمیم استقرار، دسترسی از بیرون ممنوع است و پنل خودش پراکسی می‌کند.

### نشان و نشانگر کار

نشان ویرا **شمسهٔ هشت‌پر** است — نقش هندسی معماری ایرانی: دو مربع چرخیده روی هم،
هشت‌ضلعیِ خالی در میان، و شمسهٔ کوچک‌تری درونش. همان چیزی که در کاشی‌کاری و خاتم می‌بینی.

هندسه‌اش در `ui/lib/mark.js` است و **همهٔ خروجی‌ها از همان ساخته می‌شوند**:

```bash
node tools/make-icons.mjs
```

این دستور `logo.svg`، `logo-live.svg`، شش آیکون PNG (۱۶ تا ۵۱۲) و `manifest.webmanifest`
را می‌سازد. رستر PNG را خودمان نوشته‌ایم — بدون هیچ وابستگی، فقط `zlib` خود Node — چون در
محیط توسعه نه ImageMagick هست نه sharp.

چون مانیفست و آیکون‌ها هستند، ویرا **نصب‌شدنی** است: در Chrome یا Edge روی «Install» بزن تا
در یک پنجرهٔ جدا مثل یک برنامهٔ دسکتاپ باز شود.

وقتی مدل مشغول است، **نسخهٔ متحرک همان نشان** می‌چرخد و پرتوهایش نوبتی روشن و کم‌رنگ
می‌شوند، کنارش یک جملهٔ گویا و یک ثانیه‌شمار:

```
✳  در حال خواندن فایل      ۳ ثانیه              Esc برای توقف
```

جمله با کاری که واقعاً در جریان است عوض می‌شود — «در حال فکر کردن»، «در حال استدلال»،
«در حال اجرای فرمان»، «در حال جستجو در کد»، «زیرعامل در حال کار»، «در حال بررسی نتیجه».
اگر «کاهش حرکت» را در سیستمت روشن کرده باشی، هیچ چیزی نمی‌چرخد.

### اتصال مخزن گیت

زیر کادر نوشتن، همیشه دیده می‌شود:

```
⌗ IGBZ-WP    ⑂ arena/01a00c31    +۱۷۷۳ −۸۱۲    [ ثبت ۹ تغییر ]
```

سه سؤالی که وسط یک خرابی نباید کلیک بخواهند — **کدام مخزن، کدام شاخه، چقدر عوض شده** — و
یک راه برای بستن کار.

| نشان | کلیک |
|---|---|
| مخزن | **فهرست مخزن‌هایی که به ویرا مجوز داده‌ای** (از `gh repo list`)، یا کلون یک مخزن تازه با توکن، یا تعویض پوشه |
| شاخه | فهرست شاخه‌ها، تعویض، ساخت شاخهٔ تازه |
| `+n −m` | صفحهٔ **تغییرات**: فایل‌ها، دیف هرکدام، کامیت‌های اخیر |
| دکمه | ثبت · فرستادن · درخواست ادغام |

**مخزن و شاخه، مالِ همان گفتگو هستند (از ۰.۹.۱):** در ابتدای هر گفتگوی تازه انتخابشان
می‌کنی — شاخهٔ پیش‌فرضِ مخزن خودش می‌آید — و **با فرستادن اولین پیام قفل می‌شوند** تا
گفتگوی بعدی. قفل دوطرفه است: رابط دکمه‌ها را می‌بندد و سرور هم `branch`/`use-repo` را با
۴۰۹ رد می‌کند، چون قفلِ فقط-رابطی را با یک `curl` می‌شود دور زد.

**سه قاعده که شکسته نمی‌شوند:**

۱. **هیچ‌وقت مستقیم روی `main`.** اگر روی شاخهٔ محافظت‌شده باشی و چیزی بخواهد ثبت شود،
   اول یک شاخهٔ کاری ساخته می‌شود.
۲. **توکن در خط فرمان نمی‌آید.** نه در آرگومان، نه در آدرس ریموت — از راه یک
   credential helper موقت تزریق می‌شود تا در `ps` و لاگ‌ها دیده نشود. خروجی گیت هم قبل از
   برگشتن **پاک‌سازی** می‌شود.
۳. **کامیت، پوش و ادغام هر سه تأیید می‌خواهند.** هیچ‌کدام خودکار نیست.

ابزارهای مدل: `git_status` · `git_diff` · `git_branch` · `git_commit` · `git_push` · `git_log`

### ناوبری — همه‌چیز یک کلیک دورتر

نوار کناری مستقیم به این‌ها می‌رود، بدون هیچ پنجره‌ای:

```
گفتگوها · ابزارها · کانکتورها · اسکیل‌ها · زیرعامل‌ها · فضای کار · تنظیمات
```

**فضای کار** خودش زیربخش دارد که همان‌جا باز می‌شوند: حافظهٔ پروژه، مجوزها، سندباکس،
مصرف و هزینه، وضعیت.

**همهٔ صفحه‌ها تمام‌قد باز می‌شوند، نه مودال** — با سربرگ، توضیح و دکمهٔ بازگشت به گفتگو.

**تنظیمات یک صفحه است، نه دیالوگ** — با ستون کناری خودش و چهارده بخش: پرووایدر و مدل
(چند پروفایل) · کانکتورها (MCP) · اسکیل‌ها · پلاگین‌ها · زیرعامل‌ها · دستورها · هوک‌ها ·
مجوزها · سندباکس · حافظهٔ پروژه · ابزارها · مصرف و هزینه · وضعیت و تشخیص · ظاهر.

منوی `+` داخل کامپوزر هم پرکاربردها را می‌آورد: تصویر، اشاره به فایل، حالت کار،
کانکتورها، اسکیل‌ها، ابزارها، زیرعامل‌ها، پوشهٔ کاری، بازگشت.

**و کادر گفتگو درِ ورودی همه‌چیز است.** آدرس یک اسکیل یا پلاگین را همان‌جا بینداز و بگو
«نصبش کن» — ابزار `install` نوعش را خودش تشخیص می‌دهد. یا `/install owner/repo`.

> هیچ قابلیتی «فقط با ویرایش دستی JSON» در دسترس نیست، و هیچ قابلیتی هم پشت یک دیالوگ
> قفل نیست.

## ابزارها

`read_file` · `write_file` · `edit_file` · `multi_edit` · `list_dir` · `glob` · `grep` ·
`bash` (با اجرای پس‌زمینه) · `bash_output` · `kill_shell` · `web_fetch` · `web_search` ·
`todo_write` · `exit_plan_mode` · `ask_user_question` · `notebook_edit` · `skill` · `task` ·
`read_mcp_resource` (وقتی سروری منبع داشته باشد) · و هر ابزاری که از **MCP** بیاید.

**اجرای موازی:** اگر مدل در یک نوبت چند ابزار *خواندنی* بخواهد، با هم اجرا می‌شوند و
نتیجه‌ها به همان ترتیبِ درخواست برمی‌گردند. هر چیزی که می‌نویسد یا اجرا می‌کند ترتیبی
می‌ماند — هم چون ممکن است روی هم اثر بگذارند، هم چون دروازهٔ تأیید نباید چند پنجره را با هم
جلوی کاربر بگذارد.

همه‌شان همیشه در دسترس‌اند. آنچه کنترل می‌شود **اجازه** است، نه توانایی:

| حالت | رفتار |
|---|---|
| **پلن** | فقط بررسی و خواندن. هر ابزاری که چیزی را تغییر بدهد رد می‌شود. |
| **عادی** (پیش‌فرض) | خواندن آزاد؛ نوشتن، ویرایش و اجرای فرمان **تأیید** می‌خواهند. |
| **خودکار** | همه‌چیز بدون پرسش، جز آنچه در فهرست ممنوع گذاشته‌ای. |

قاعده‌ها در `~/.vira/config.json` و می‌توانند پیشوندی باشند:

```json
{
  "permissions": {
    "mode": "default",
    "allow": [ "bash:git status", "bash:npm test" ],
    "deny":  [ "bash:rm -rf" ]
  }
}
```

**فرمان مرکب، تکه‌تکه سنجیده می‌شود.** قاعدهٔ `bash:git` به `git status` اجازه می‌دهد ولی
به `git status && rm -rf /` **نه** — چون `rm` قاعده‌ای ندارد. جداکننده‌های `&&`، `||`، `;`
و `|` شکسته می‌شوند و **هر تکه** باید جداگانه مجاز باشد. اگر فرمان جانشینی داشته باشد
(`$(…)` یا بک‌تیک)، قاعدهٔ پیشوندی اصلاً اعمال نمی‌شود، چون آنچه اجرا می‌شود در متن پیدا
نیست. برای «ممنوع» برعکس است: **یک تکه** کافی است تا کل فرمان رد شود.

دکمهٔ «همیشه اجازه بده» هم برای فرمان مرکب **چند قاعده** می‌سازد، نه یکی — و برای
`git`/`npm`/`docker`/… قاعده دو کلمه‌ای است (`bash:git status`، نه `bash:git`)، چون اجازه
به `git` یعنی اجازه به `git push --force`.

**محدودهٔ کار:** ابزارهای فایل فقط داخل «پوشهٔ کاری» کار می‌کنند؛ مسیر بیرون از آن رد می‌شود.

## سندباکس اجرای فرمان

پیش‌فرض **روشن** است (از ۰.۹.۱). `bash` و شل‌های پس‌زمینه داخل یک کانتینر
(Docker یا Podman) اجرا می‌شوند:

```
شبکه بسته (--network none) · سقف حافظه و CPU · --cap-drop ALL · no-new-privileges
پوشهٔ کاری روی /work سوار می‌شود و همان‌جا پوشهٔ جاری است
```

خواندن و نوشتن فایل روی سیستم خودت می‌ماند — این‌ها همین حالا هم به پوشهٔ کاری محدودند و
بردنشان به کانتینر فقط کندی می‌آورد.

> **روی ویندوز به Docker Desktop با WSL2 نیاز داری.** اگر نداری و می‌خواهی ویرا مستقیم
> روی پروژهٔ واقعی کار کند، **تنظیمات ← سندباکس** را خودت خاموش کن. این تصمیمِ مدیر است،
> نه پیش‌فرضِ ابزار: قاعدهٔ کارفرما این است که ویرا بدون اجازه دست به پروژهٔ گیت نزند.

**سیاست شکست، بسته است:** اگر سندباکس روشن باشد ولی Docker پیدا نشود، فرمان **اجرا
نمی‌شود**. قابلیت امنیتی‌ای که بی‌سروصدا به حالت ناامن برگردد، از نداشتنش بدتر است. اگر
عمداً برگشت به میزبان را می‌خواهی، در تنظیمات صریح روشنش کن.

تنظیمات → **سندباکس**: موتور، ایمیج، شبکه، سقف منابع، ریشهٔ فقط‌خواندنی، مسیرهای اضافه، و
دکمهٔ **تست سندباکس** که واقعاً یک کانتینر بالا می‌آورد.

| ایمیج پیشنهادی | برای |
|---|---|
| `node:22-bookworm-slim` | جاوااسکریپت (پیش‌فرض) |
| `php:8.3-cli` | پروژهٔ PHP/وردپرس |

روی ویندوز به **Docker Desktop با WSL2** نیاز داری.

## کانکتورها (MCP)

`stdio` (اجرای فرمان محلی) و `HTTP`، در محدودهٔ سراسری یا فقط همین پروژه، با ویرایشگر
متغیر محیطی و هدر. دکمهٔ «تست اتصال» واقعاً وصل می‌شود و فهرست ابزارها را برمی‌گرداند.

**پرامپت‌های MCP** خودکار به دستور اسلش تبدیل می‌شوند (`/mcp__<سرور>__<پرامپت>`) و
**منابع MCP** با ابزار `read_mcp_resource` خوانده می‌شوند.

فایل‌های زیر هم مثل قبل کار می‌کنند (اگر ترجیح می‌دهی دستی بنویسی):

```json
{
  "mcpServers": {
    "files":  { "command": "npx", "args": [ "-y", "@modelcontextprotocol/server-filesystem", "." ] },
    "remote": { "url": "https://example.com/mcp", "headers": { "Authorization": "Bearer …" } }
  }
}
```

در `~/.vira/config.json` (سراسری) یا `<پروژه>/.vira/mcp.json` (پروژه‌ای).
ابزارهای هر سرور با نام `mcp__<سرور>__<ابزار>` می‌آیند تا در قواعد مجوز جدا نشانه‌پذیر باشند.
یک سرور خراب، بالا آمدن برنامه را نمی‌خواباند؛ وضعیتش در پنل **افزونه‌ها** دیده می‌شود.

دستور خودت: هر فایل مارک‌داون در `~/.vira/commands/` یا `<پروژه>/.vira/commands/`

```markdown

description: بازبینی یک فایل با تمرکز مشخص
---

```

`$ARGUMENTS` کل ورودی است و `$1`،`$2`… پارامترهای جدا. در کادر ورودی با `/` فهرست
دستورها با تکمیل خودکار باز می‌شود.

## هوک‌ها

هر هوک یک فرمان پوسته است که JSON روی stdin می‌گیرد.

```json
{
  "hooks": {
    "PreToolUse":      [ { "matcher": "bash", "command": "./scripts/audit.sh" } ],
    "UserPromptSubmit":[ { "command": "echo '{\"additionalContext\":\"شاخه: main\"}'" } ]
  }
}
```

رویدادها: `SessionStart` · `UserPromptSubmit` · `PreToolUse` · `PostToolUse` · `Stop` ·
`SessionEnd`.
**توقف:** خروج با کد ۲ یا چاپ `{"decision":"block","reason":"…"}`.
**کانتکست اضافه:** چاپ `{"additionalContext":"…"}` یا هر متن خام.

هوک `PreToolUse` حتی جلوی ابزارِ *مجاز* را هم می‌گیرد — این نقطه، جای سیاست سازمانی است.

## زیرعامل، چک‌پوینت و کانتکست

- **`task`**: یک نشست تازه با بودجهٔ خودش که فقط **خلاصهٔ نتیجه** را برمی‌گرداند. برای
  کاوش‌های طولانی که کانتکست اصلی را خراب می‌کنند. زیرعامل خودش `task` ندارد (جلوی بازگشت
  بی‌پایان).
- **زیرعامل تعریف‌شده**: هر فایل `~/.vira/agents/<نام>.md` (یا `<پروژه>/.vira/agents/`)
  یک متخصص با پرامپت، مدل و ابزارهای خودش است؛ مدل با `subagent_type` صدایش می‌زند.
  ساختنش از **تنظیمات → زیرعامل‌ها**.
- **چک‌پوینت و بازگشت**: قبل از هر پیام تو یک چک‌پوینت باز می‌شود و قبل از هر تغییرِ فایل،
  نسخهٔ فعلی‌اش پشتیبان گرفته می‌شود. با `Esc Esc` یا `/rewind` می‌شود فایل‌ها را به همان
  لحظه برگرداند و گفتگو را هم تا همان‌جا برید.
- **فشرده‌سازی**: گفتگوی بلند خودکار (یا با `/compact`) به یک خلاصه تبدیل می‌شود. اگر
  خلاصه‌سازی شکست بخورد، گفتگو دست‌نخورده می‌ماند.
- **`VIRA.md`** در ریشهٔ پروژه، همیشه در پرامپت سیستمی می‌نشیند — همان نقش دستورالعمل
  پروژه.

## تست

```bash
node test/run.mjs                 # ۳۷۵ تست واحد (~۳۰ ثانیه)
node test/run.mjs --only رابط     # فقط یک بخش — برای حلقهٔ کار (~۱۲ ثانیه)
node test/run.mjs --only 'دکمه|آیکون'
node test/live.mjs                # ۴۴ آزمون زنده روی یک سرور واقعی
```

`--only` هم با نام بخش جور می‌شود هم با نام تست. **حین کار** به‌کار می‌آید؛ ملاکِ تحویل
همیشه اجرای کامل است — سوئیتِ نصفه‌اجراشده چیزی را تأیید نمی‌کند.

**۳۷۵ تست واحد، بدون وابستگی.** ابزارها، مجوزها، اسکیل، دستور، هوک، فشرده‌سازی، هر دو
پروتکل پرووایدر (با سرور جعلی)، زیرعامل، MCP (با یک سرور MCP واقعی)، پلاگین، حلقهٔ عامل،
دیف، چک‌پوینت، کانکتور، عامل‌ها، شل پس‌زمینه، جستجوی فازی، هزینه، خروجی گفتگو،
محتوای چندرسانه‌ای، تصویر و استدلال در هر دو پروتکل، اجرای موازی، SDK، پرامپت/منبع MCP،
نوت‌بوک Jupyter، آرگومان‌سازی و سیاست شکستِ سندباکس، و **گیت روی یک مخزن واقعی** —
شاخهٔ محافظت‌شده، ماسک توکن، دیف و آمار.

از ۰.۷ به‌علاوه: **کل هاب** — تشخیص جنس درخواست، نُه راهبرد مسیریابی (هرکدام با نمونهٔ
ساختگی که ثابت می‌کند واقعاً همان را انتخاب می‌کند)، شکست و برگشت، مدارشکن، پایان اعتبار،
سقف هزینه، کش، امضای خطا، هر هشت عملیات وصله، دفتر راه‌حل‌ها، هر چهار پلهٔ عیب‌یاب، و
یک هاب واقعی روی سرور ساختگی که ۴۰۴ می‌دهد تا نردبان تعمیر از اول تا آخر اجرا شود.

و **صفحه‌های رابط واقعاً اجرا می‌شوند**: یک DOM کوچک در `test/fake-dom.mjs` هست که هر پنج
صفحهٔ هاب را می‌سازد، دکمه‌ها را می‌زند، و درخواست‌های خروجی را می‌سنجد. دلیلش یک تجربهٔ
واقعی است: تست `grep` ثابت می‌کند رشته‌ای در کد هست، ولی ثابت نمی‌کند صفحه در مرورگر سفید
نمی‌ماند.

**۴۴ آزمون زنده.** سرور واقعی بالا می‌آید، SSE وصل می‌شود، و همان مسیرهایی صدا زده می‌شوند
که رابط کاربری صدا می‌زند: دروازهٔ تأیید، دیف، بازگشت، کارت نقشه، کارت پرسش، شل پس‌زمینه،
افزودن و حذف کانکتور MCP، پرامپت MCP، پیوست تصویر، ساخت زیرعامل و دستور، خروجی گفتگو، و
اجرای واقعی `vira -p` در یک پروسهٔ جدا، و سندباکس با یک موتور کانتینر جعلی در PATH
(تنها راه آزمودن مسیرِ کانتینر در محیطی که داکر ندارد).

قاعده‌ای که از مخزن اصلی می‌آید: **سوئیتی که بار اول سبز شود چیزی ثابت نکرده.** هر تست
اینجا با خراب‌کردن عمدی کد قرمز شده است.
