# پرامپت برای Codex — رفع مشکلات ویرا در محیط واقعی

> این فایل را **کامل** به Codex بده. از «## ۰» تا آخر، همه‌اش بخشی از دستور است.

---

## ۰. تو کی هستی و چرا اینجایی

تو روی مخزن `paymanshafayan/IGBZ-WP` کار می‌کنی، پوشهٔ `vira/` — یک ابزار عاملِ
Node.js با رابط وب که فارسی و راست‌به‌چپ است.

**قبل از تو، یک عامل دیگر سه دور روی این مشکلات کار کرد و هر سه بار شکست خورد.**
کارفرما بعد از آخرین دور گفت: **«هیچ چیز درست نشده.»**

دلیل شکست، مهم‌ترین چیزی است که باید بدانی:

> عامل قبلی **در سندباکسی بدون مرورگر، بدون xray و بدون اینترنت آزاد** کار می‌کرد.
> باگ‌ها را از روی **خواندن کد** تشخیص می‌داد، تست واحد می‌نوشت، تست‌ها سبز می‌شدند،
> و گزارش «انجام شد» می‌داد. ولی تست‌ها همهٔ مسیرهای شبکه و همهٔ رندر مرورگر را
> **دابل** می‌کردند — پس هیچ‌کدام از باگ‌های واقعی هرگز اجرا نمی‌شدند.

یک نمونهٔ واقعی از همان شکست، تا بفهمی خطر چقدر جدی است: کد تست تونل این بود

```js
await fetch( url, { dispatcher: socksDispatcher( { url: new URL( 'socks5://...' ) } ) } )
```

و **دو** باگ مستقل در همین یک خط بود — `fetch` سراسری Node اصلاً داسپچر undici را
قبول نمی‌کند، و `socksDispatcher` هم `{url}` نمی‌گیرد بلکه `{type,host,port}`
می‌خواهد. یعنی تست تونل **صددرصد** شکست می‌خورد، صرف‌نظر از سالم بودن سرور. تست‌های
واحد سبز بودند چون شبکه دابل شده بود. این دو باگ فقط وقتی معلوم شدند که کد
**واقعاً اجرا شد**.

**پس قانون شمارهٔ یک تو:** هیچ بندی را «تمام‌شده» اعلام نکن مگر آن را در محیط واقعی
اجرا کرده باشی و خروجی واقعی را دیده باشی. برای رابط کاربری یعنی **مرورگر واقعی**
(Playwright یا Puppeteer نصب کن)، برای شبکه یعنی **سوکت واقعی**.

## ۱. راه‌اندازی

```bash
cd vira
npm ci
node src/cli.js --port 7788 --no-open     # رابط: http://127.0.0.1:7788
node test/run.mjs                          # ۳۷۷ موفق، ۱ ناموفق (داکر، محیطی — بی‌خیالش)
```

نسخهٔ فعلی `0.9.9`. آخرین کامیت `b3538fd`.

**قواعد اجباری پروژه** (تست‌ها این‌ها را گارد می‌کنند و اگر رعایت نکنی قرمز می‌شوی):

| قاعده | توضیح |
|---|---|
| هر `<button>` کلاس `btn` بگیرد | تابع `h('button', { class: 'btn ...' })` |
| CSS بدون سلکتور تکراری | یک سلکتور دو بار تعریف نشود |
| CSS بدون کلاس مرده | هر کلاس تعریف‌شده باید جایی استفاده شود |
| `ui/lib/icons.js` تولیدشده است | دستی ویرایش نکن؛ فقط از ۷۹ آیکون موجود (`play` وجود ندارد) |
| نسخهٔ `package.json` با هر تغییر بالا برود | ⇐ `0.9.10` |
| رابط کاملاً فارسی و RTL | هر رشتهٔ تازه باید ترجمه داشته باشد |

**تله‌های محیطی که وقتت را می‌گیرند:**
- `node test/run.mjs` بلوک خلاصه/خروج در انتهای فایل دارد؛ تست تازه را **قبل** از
  آن درج کن وگرنه بی‌صدا اجرا نمی‌شود.
- `ui/thread.js` را نمی‌شود مستقیم import کرد (زنجیرهٔ `ui/lib/voice.js`)؛ از
  `bootApp()` در `test/run.mjs` استفاده کن.
- برای اسکریپت موقت `.mjs`، فایل را **داخل `vira/`** بساز نه `/tmp`.

## ۲. فهرست کامل مشکلات

پنج بند. **بند ۱ و ۲ حیاتی‌اند — برنامه بدون آن‌ها اصلاً کار نمی‌کند.** بند ۳ تا ۵
رابط کاربری‌اند و کارفرما هر سه را با تصویر رد کرده.

---

### 🔴 مشکل ۱ — هاب کار نمی‌کند: مدل نامعتبر `:batch` و عدم سوییچ روی ۴۲۹

**عین چیزی که کارفرما روی صفحه دید:**

```
هر ۳ مسیر شکست خورد.
«openai/gpt-4o-mini:batch»: مدل پیدا نشد.
«gpt-4.1-mini»: ۴۲۹.
«gpt-4.1-mini-2025-04-14»: ۴۲۹.
```

این خروجی **دو** باگ جدا را لو می‌دهد:

#### ۱-الف) شبه‌مدل‌ها وارد فهرست نامزدها می‌شوند

`openai/gpt-4o-mini:batch` یک مدل چت نیست؛ نقطهٔ انتهایی Batch API است و در
`/chat/completions` جواب «مدل پیدا نشد» می‌دهد. کشف خودکار مدل‌ها این‌ها را از
`GET /models` می‌گیرد و کورکورانه وارد رجیستری می‌کند.

`src/hub/registry.js` فقط یک فیلتر ضعیف دارد (خط ۲۳):

```js
const NO_TOOLS = /embed|whisper|tts|dall-e|stable-diffusion|flux|rerank|moderation|clip|bge-|e5-/i;
```

این فقط `caps.tools=false` می‌گذارد و مدل را **حذف نمی‌کند**. هیچ الگویی هم برای
`:batch` ندارد.

**آنچه باید بکنی:** مدل‌هایی که برای چت قابل استفاده نیستند اصلاً وارد رجیستری
نشوند (یا `missing:true` بخورند). دست‌کم این‌ها: پسوند `:batch`، و همچنین
`*-embedding-*`, `tts-*`, `whisper-*`, `dall-e-*`, `*-audio-*`, `*-realtime-*`,
`*-moderation-*`, `omni-moderation-*`, `*-transcribe`, `*-search-preview`.

⚠️ **مراقب باش زیادی حذف نکنی.** `gpt-4o-audio-preview` باید برود ولی
`gpt-4o` باید بماند. کارفرما **۵۳۲ مدل** روی ۴ اتصال دارد؛ اگر فیلترت پرخور باشد
مدل‌های سالم را می‌کشد. بعد از نوشتن فیلتر، **فهرست واقعی مدل‌های OpenAI را
بگیر و چاپ کن** که چند تا و کدام‌ها حذف شدند.

#### ۱-ب) روی ۴۲۹، فقط مدل بعدیِ همان پرووایدر امتحان می‌شود ← این باگ اصلی است

در خروجی بالا دقت کن: هر سه تلاش **مال OpenAI‌اند**. کارفرما Gemini فعال دارد، ولی
هرگز امتحان نشد.

۴۲۹ یعنی «سهمیهٔ **این حساب** پر است». امتحان کردن مدل دیگرِ همان حساب **قطعاً**
دوباره ۴۲۹ می‌دهد. باید به **اتصال دیگر** پرید.

مسیر کد:
- `src/hub/index.js:~438` — حلقهٔ fail-over:
  ```js
  const maxAttempts = Math.min( this.data.routing?.maxAttempts || 3, routed.candidates.length );
  for ( let i = 0; i < limit; i++ ) {
      const candidate = routed.candidates[ i ];   // ← فقط ترتیبی جلو می‌رود
  ```
- `src/hub/router.js:136` — `sortBy()` که ترتیب را می‌سازد و هیچ تنوعی از نظر
  اتصال تضمین نمی‌کند.
- `src/errors.js:55` — اینجا ۴۲۹ به `kind` تبدیل می‌شود.
- `src/hub/health.js:~102` — فقط `kind === 'credit'` باعث `exhausted` می‌شود.

**آنچه باید بکنی:** وقتی خطا ۴۲۹/rate-limit است، نامزدهای **همان `connectionId`** را
از ادامهٔ حلقه رد کن و برو سراغ اولین نامزدی که اتصالش فرق دارد. همچنین
`maxAttempts: 3` وقتی هر ۳ تا یک اتصال‌اند بی‌معنی است.

⚠️ `src/hub/repair.js:285` روی ۴۲۹ یک `backoff_retry` تا ۳ بار دارد. تصمیم بگیر
این با پرش به اتصال بعدی چطور کنار می‌آید — احتمالاً پرش باید **قبل** از backoff
باشد، چون وقتی اتصال سالم دیگری هست، صبر کردن بی‌معنی است.

**چطور واقعاً تستش کنی:** دو اتصال جعلی بالا بیاور (سرور HTTP محلی): اولی همیشه
۴۲۹، دومی جواب سالم. تأیید کن که پاسخ از دومی می‌آید و در `tried` هم دو **اتصال
متفاوت** ثبت شده. بدون این تست، بند ۱-ب را تمام‌شده حساب نکن.

### 🔴 مشکل ۲ — تست کانفیگ‌ها حتی یک کانفیگ سالم برنمی‌گرداند

کارفرما کانفیگ‌های V2Ray/Hiddify را وارد می‌کند، «تست همه» می‌زند، و **همه** خراب
اعلام می‌شوند — حتی آن‌هایی که در Hiddify سالم کار می‌کنند.

دور قبل **دو باگ داسپچر** در `src/tunnel/engine.js` و `src/net.js:~101` پیدا و
اصلاح شد (توضیحش را در بخش ۰ خواندی). آن اصلاح **درست بود** و با SOCKS5 محلی هم
تأیید شد — ولی کارفرما می‌گوید هنوز کار نمی‌کند. **یعنی باگ سومی هست که در سندباکس
دیده نشد**، چون آنجا نه xray بود نه اینترنت.

مسیر کد:
- `src/tunnel/core.js:18` — دانلود و اجرای باینری xray
- `src/tunnel/parse.js:48` — `parseLink()` برای `vmess://`, `vless://`, `trojan://`, `ss://`
- `src/tunnel/engine.js` — `probeThrough()~176`, `testAll()~295`, `healthCheck()~501`

**آنچه باید بکنی — با کانفیگ واقعی، نه دابل:**

۱. اول ثابت کن xray اصلاً بالا می‌آید: دانلود شد؟ اجرا شد؟ کانفیگ JSON که برایش
   نوشته می‌شود معتبر است؟ **`stderr` خود xray را چاپ کن** — به احتمال زیاد جواب
   همان‌جاست و کسی تا حالا نگاهش نکرده.
۲. هر چهار شمای لینک را با نمونهٔ واقعی پارس کن و JSON خروجی را با چیزی که xray
   انتظار دارد مقایسه کن.
۳. مسیر کامل را اجرا کن: لینک → کانفیگ xray → بالا آمدن پورت محلی → تماس از راهش.

**منطق دومرحله‌ای که کارفرما صریحاً خواسته** (نقل قول مستقیم):

> «در تست کانفیگ‌ها، از طریق آن‌ها یک پرووایدر فعال را تست کند و در صورت اتصال
> موفق کانفیگ را سالم اعلام کن. البته بعد از تست اولیه، که کانفیگ‌های غیرفعال را
> بی‌خود تست نگیرد.»

یعنی: **مرحلهٔ ۱** همهٔ کانفیگ‌ها را با یک مقصد سبک تست کن. **مرحلهٔ ۲** فقط روی
بازماندگان، یک پرووایدر واقعی را صدا بزن. قرارداد داده‌ای که قبلاً تعریف شده و
باید حفظ شود: `c.ok1` (اینترنت)، `c.serviceOk` (`null` = آزموده‌نشده)،
`c.ok = serviceUrl ? serviceOk : ok1`، به‌علاوهٔ `c.ms`/`c.serviceMs`/`c.error`.

⚠️ **۴۰۱ و ۴۰۳ یعنی تونل سالم است** — یعنی به سرویس رسیدیم و او کلید را نپسندید.
اشتباهاً «خراب» علامتشان نزن.

**نمایش انتظار** (نقل قول مستقیم کارفرما):

> «در زمان تست کانفیگ‌ها و لود روی xray، با نمایش یک آیکون لودر و یا پروگرس‌بار
> وضعیت انتظار را به کاربر نمایش دهد.»

زیرساختش از قبل هست: `S.testing = {phase, done, total, healthy, internetOnly,
broken, name, service, cancelled, startedAt}` که در `broadcast(progress)` و
`GET /api/tunnel` می‌رود، `POST {action:'cancel-test'}` برای لغو، و
`paintProgress()` در `ui/proxy.js`. **در مرورگر واقعی چک کن که واقعاً حرکت می‌کند.**

### 🟠 مشکل ۳ — نقشهٔ توپولوژی هنوز شبیه مرجع نیست

مرجع: `_bin/Snap10.jpg` و بقیهٔ `_bin/Snap*.jpg` (رابط **OmniRoute**).
شکایت کارفرما با تصویر `Snap20.jpg` آمد.

کد: `ui/hubpage.js:~240-350`، CSS از `ui/style.css:3674`.

چهار ایراد مشخص:

1. **چیدمان قرینه نیست.** الان `posOf()` زاویه را از `i / count` می‌سازد. با
   تعداد کم گره، پخش نامتوازن می‌شود.
2. **یال‌ها واقعاً متحرک نیستند.** باید بررسی کنی که انیمیشن در مرورگر واقعاً
   اجرا می‌شود.
3. **برچسب «هاب فعال» با چیزهای دیگر همپوشانی دارد.**
4. **بعضی گره‌ها اصلاً یال ندارند.** هر گره باید یال داشته باشد.

**مشخصات یال‌ها — خواستهٔ صریح کارفرما، بدون تغییر:**

| وضعیت | ظاهر |
|---|---|
| `active` | نقطه‌چین **سبز متحرک**، جهت حرکت **از هاب به سمت پرووایدر** |
| `recent` | خط **ممتد** هم‌رنگ وضعیت |
| `error` | خط **ممتد** هم‌رنگ وضعیت |

پرووایدرها باید **مستطیل‌های کوچک** باشند (الگوی OmniRoute)، نه کارت.

نکات فنی که قبلاً کشف شده و به دردت می‌خورد:
- `direction: ltr` روی `.topo` **لازم است**، وگرنه در RTL نقشه آینه می‌شود و
  نقطه‌ها برعکس حرکت می‌کنند.
- برای جهت حرکت: `x1,y1` = مرکز ⇐ `x2,y2` = پرووایدر، با `stroke-dashoffset: -9`
  (مجموع `dasharray: 2 7`).

## ۳. روش کار — این بخش را جدی بگیر

### ۳-۱. اول محیط تست واقعی بساز، بعد کد بزن

```bash
npm i -D playwright && npx playwright install chromium
```

عامل قبلی این را نداشت و برای همین هر پنج بند رابط را «سبز» دید و کارفرما هر پنج
تا را رد کرد. **بدون مرورگر واقعی، بندهای ۳/۴/۵ را اصلاً شروع نکن.**

برای بندهای ۱ و ۲ هم همین: سرور HTTP محلی که ۴۲۹ می‌دهد، SOCKS5 واقعی، xray واقعی.

### ۳-۲. هر رفع را با جهش (mutation) ثابت کن

بعد از سبز شدن تست، **کد را عمداً به حالت باگ‌دار برگردان** و مطمئن شو تست قرمز
می‌شود. اگر قرمز نشد، تستت بی‌ارزش است. این تنها روشی است که جلوی «تست سبزِ
بی‌معنی» را می‌گیرد.

### ۳-۳. تصاویر مرجع را واقعاً باز کن

`_bin/Snap4.jpg`, `Snap10.jpg` و بقیه. برای بندهای ۳ و ۴ نمی‌شود از روی توضیح متنی
کار کرد — باید تصویر را ببینی و مقایسه کنی.

### ۳-۴. برای هر بند، این سه چیز را گزارش کن

1. **ریشهٔ واقعی** (نه علامت) — کدام خط، چرا.
2. **اثبات اجرای واقعی** — خروجی واقعی، لاگ، یا اسکرین‌شات.
3. **جهش** — چه چیزی را خراب کردی و تست چطور قرمز شد.

اگر بندی را نتوانستی در محیط واقعی تأیید کنی، **صریح بنویس «تأیید نشد»**. گزارش
دروغِ «انجام شد» بدترین حالت ممکن است — دقیقاً همین سه دور را سوزاند.
