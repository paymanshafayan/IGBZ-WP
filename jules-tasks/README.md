# پوشهٔ `jules-tasks/` — صف تسک‌های جولز (Google Jules)

> ثبت: ۱۴۰۶/۰۶/۰۲ · بخشی از خط لولهٔ «اتوماسیون توسعه با جولز» (گزینهٔ ب — تمام‌خودکار)

## چرخهٔ کار

```
۱. ایجنت (یا کارفرما) یک فایل TASK-*.md در این پوشه پوش می‌کند
۲. GitHub Action «Jules Dispatcher» (.github/workflows/jules-dispatcher.yml)
   خودکار یک session در API جولز می‌سازد (کلید: Secrets → JULES_API_KEY)
۳. جولز در VM خودش کار می‌کند و در پایان PR باز می‌کند (AUTO_CREATE_PR)
۴. ایجنت PR را بازبینی فنی + تست ویژوال (قانون ۱۲) می‌کند و روی PR کامنت می‌گذارد
۵. تصمیم merge همیشه با کارفرماست
```

## قواعد فایل تسک

- نام فایل: `TASK-<شمارهٔ سه‌رقمی>-<slug>.md` (مثال: `TASK-001-modules-test.md`)
- **کل محتوای فایل به‌عنوان پرامپت به جولز فرستاده می‌شود** — پس:
  - بدنهٔ تسک **به انگلیسی** نوشته شود (کیفیت خروجی مدل بالاتر است)
  - سطر اول: `# TASK-NNN: <عنوان کوتاه>`
  - متادیتا در ابتدای فایل به‌صورت کامنت HTML (dispatcher می‌خواند):
    - `<!-- branch: main -->` — شاخهٔ مبدأ (پیش‌فرض main؛ هرگز شاخه‌های arena)
  - بخش‌های الزامی: `## Context` · `## Task` · `## Constraints` · `## Acceptance criteria`
- در `## Constraints` قواعد دائمی پروژه که به تسک مربوط‌اند تکرار شوند، از جمله:
  - هرگز `rand()`/`mt_rand()` — فقط `random_int()`/`Crypto`
  - SQL فقط MySQL؛ هرگز `__()` قبل از هوک `init`
  - شمار جدول‌ها (`CREATE TABLE`) بدون تصمیم صریح تغییر نکند
  - تست با `bash _devenv/test.sh` (php-wasm) — `php` مستقیم در PATH نیست
  - تغییر حداقلی؛ خارج از دامنهٔ تسک هیچ فایلی دست نخورد
- **ضد-تکرار:** dispatcher برای هر تسکِ ارسال‌شده یک مارکر در
  `jules-tasks/.dispatched/<نام فایل>.json` کامیت می‌کند (شامل شمارهٔ session).
  تا وقتی مارکر هست، ویرایش فایل تسک دوباره ارسال نمی‌شود؛ برای ارسال مجدد،
  مارکر را حذف کنید.
